# Pi Token Monitor Usage

This document describes how to use the Pi coding agent token usage monitor. For installation and shared workflows, see the main [README.md](./README.md).

## Pi Usage

The Pi token usage monitor tracks tokens used by Pi sessions and aggregates usage across different models and providers.

### Ingest command

Ingest Pi agent session token usage and checkpoints into the local DuckDB database:

```bash
uv run pi-token-usage ingest
```

Useful options:

- `--source-dir`, `-s`: Path to the Pi agent sessions root directory (default: `~/.pi/agent/sessions`).
- `--database-path`, `-d`: Path to the DuckDB database file (default: `~/.local/share/coding-agent-token-monitors/token_usage.duckdb`).
- `--full-refresh`: Bypass the file-state cache and per-session checkpoints to re-ingest and re-upsert every row.
- `--verbose`, `-v`: Enable info-level logs.

Examples:

```bash
# Ingest from default Pi agent sessions directory
uv run pi-token-usage ingest

# Ingest from a custom sessions path into a specific database
uv run pi-token-usage ingest --source-dir /path/to/sessions --database-path data/token_usage.duckdb

# Force a full re-ingestion of all session data
uv run pi-token-usage ingest --full-refresh
```

After ingestion, the command prints an ingestion summary (e.g. files scanned, files ingested, sessions ingested, and any parse errors) along with daily token usage and cost statistics for the last 7 days.

---

### Stats command

Aggregate and print daily token usage, token breakdowns, and costs from the local DuckDB database:

```bash
uv run pi-token-usage stats
```

Useful options:

- `--database-path`, `-d`: Path to the DuckDB database file (default: `~/.local/share/coding-agent-token-monitors/token_usage.duckdb`).
- `--timezone`, `-tz`: Timezone for daily grouping (e.g. `UTC` or `America/New_York`). Defaults to the local system time.
- `--since`: Include only usage on/after a date (`YYYY-MM-DD`).
- `--until`: Include only usage before a date, exclusive (`YYYY-MM-DD`).
- `--provider`: Include a daily token usage breakdown table aggregated by provider.
- `--verbose`, `-v`: Enable info-level logs.

Examples:

```bash
# Display daily usage stats from the default database
uv run pi-token-usage stats

# Display daily usage stats with provider breakdowns
uv run pi-token-usage stats --provider

# Filter daily usage stats by date range and timezone
uv run pi-token-usage stats --since 2026-05-01 --until 2026-06-01 --timezone America/New_York
```

## Internal Workflows

### Session Discovery and Bookkeeping
- **Session Directories**: The tool recursively scans the Pi sessions root directory for `*.jsonl` files.
- **Incremental Ingestion**: To remain highly performant, it uses a DuckDB table `pi_ingestion_files` to record the last modification time and size of successfully processed session files. Unmodified files are skipped on subsequent runs.
- **Per-Session Checkpoints**: Within each session file, it tracks the last-ingested event timestamp and ID. It only parses and appends new lines added since the last checkpoint, unless `--full-refresh` is supplied.

### Event Log Parsing
The Pi coding agent records session logs as a series of line-delimited JSON objects. The parser processes three distinct types of events:

1. **`type: "session"` (Line 1 Metadata)**:
   Must be the first line of the log. It defines the session's ID, protocol version, start timestamp, and current working directory (`cwd`). If `cwd` is omitted or empty on line 1, the parser attempts to recover it from the parent directory's folder layout, outputting a warning log if it does so.

2. **`type: "message"` (Assistant Events)**:
   Represents conversational outputs generated by the agent. If the message `role` is `assistant` and includes a `usage` dictionary containing input and output token counts, the parser extracts:
   - `input_tokens` and `output_tokens`
   - Optional `cacheRead` (`cache_read_tokens`) and `cacheWrite` (`cache_write_tokens`) counts
   - Optional `totalTokens` (`total_tokens`)
   - Optional developer-reported token costs in USD (`pi_reported_cost_*`)
   - `provider` (`provider_code`) and `model` (`model_code`)

3. **`type: "branch_summary"` and `type: "compaction"` (Context Summarization)**:
   Represents internal context condensation and compression. Similar to assistant messages, these events contain token usage counts and model pricing details under their `details.usage` object. The monitor tracks these to provide a complete picture of the agent's background operational costs.
